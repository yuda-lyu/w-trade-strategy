# 經驗(w-trade-strategy)

> 執行時之累積經驗,留給後續嘗試、執行、判斷;規則見 `../rule/rulebook.md`,現況見 `../state/state.md`。

1. **抽提管線為套件,先找出全部「標的專屬常數」**:使用端既有管線把 z-score 之 avg／std、溢價指數側之偏移參數、訓練期終點、序列 key 前綴、標的名稱寫死於各段程式;套件化時逐一改為設定參數或「首次自算並凍結於 meta」,否則換標的就失真。驗法:以原定義(含原常數)餵回套件,與既有管線之產物逐值比對為 0 差才算抽對(2026-11-08 某實測:全部序列檔逐值相同)。
2. **內建定義目錄不手抄**:由原定義檔以腳本產生(去除常數、加 id／fields),再以逐值比對驗證;手抄 136 個輸出必有錯漏。
3. **外部數據之通用性靠欄位宣告**:每個定義列出 calc 實際存取之 K 線欄位(依 calc 原始碼核對,不憑名稱猜),數據缺欄即整個定義剔除並列原因,而不是算出 NaN 序列。
4. **worker_threads 之長駐迴圈不會自行退出**:`parentPort.on('message')` 撐住執行緒,主程序收到 `done`／`error` 必 `terminate()`;冒煙時以 `| tail` 管線跑看不到任何輸出,長流程之冒煙要寫 log 檔。
5. **停止條件要在 worker 之迴圈邊界生效**:worker 自行連續起下一輪時,主程序之 stop 訊息趕不上,總輪數超出 `maxRounds` 達 `2 × workers`;改為每輪結束等主程序放行(`continue`)才起下一輪,超出至多 `workers − 1`。
6. **依隨機性或時間之測試斷言先算清**:`maxTimeMs: 1` 於準備快於 1 ms 時會跑完第 1 輪才停(斷言寫 `nRounds ≤ 1`);合成數據之因子類別數、週期數、終點時刻皆由程式決定,寫斷言前先算。
7. **(已被第 22 條取代)週期由 K 線週期換算,不由標籤硬改**:曾以 `barsPerDay = 86400 / intervalSec` 併入每次 calc 呼叫,標籤維持時間語意(`'1day'` 於 1hr K 線為 24 根);w-data-trade 1.0.50 移除 `opt.barsPerDay`,改為根數為本(見第 22 條)。
8. **估時(某實測,真實 4hr 數據)**:buildParams 全目錄(含 index 校正)約 43 秒;sweepSingle 每因子約 0.7 秒(4 worker);solve 加速版一輪約 33 秒;合成 900 根整條管線 15 秒內。
9. **UMD dist 不可把 ESM 自有套件列為 external**:rollup UMD 的 CJS 路徑以 `require()` 取外部模組並直接當預設匯出用;Node 對 ESM 檔 `require()` 回命名空間物件(`{ default }`),故把自有套件(皆 ESM)的 `src/` 深層路徑列為 external 時,dist 可載入、鍵集合也對,但執行 `buildParams` 即拋 `dataConvert is not a function`,且 `dist.readStrategies` 之 `typeof` 變 `object`。**只比對匯出鍵不夠,要比 `typeof` 並實跑**。正解:自有套件、wsemi、lodash-es 一律打包進 dist(external 只留 node 內建模組與 dayjs),ESM 專用第三方套件(`strip-bom-stream` 等)亦打包。自有套件以正則型 external 列出之寫法,`rollupFiles` 雖接受,但產物不可用(2026-11-08 實測)。
10. **測試中的 worker 數必須寫死**:`sweepSingle`／`sweepPairs` 預設 `takeLimit` 為 `os.availableParallelism() - 1`,會隨核數放大;所有測試與範例皆給 `takeLimit: 2`、`solve` 之 `workers` 為 0／1／2,新增測試延用。
11. **公開庫之去識別守門只守通用樣式**:把使用端專案名、目錄名、腳本名寫進守門正則或自檢字串,守門本身就把名稱公開了。`unit-package` ⑥ 只守磁碟機絕對路徑、使用者家目錄路徑、IPv4、權杖與私鑰樣式,自檢字串用中性假值(權杖以拼接組成避免被金鑰掃描誤報);名稱之偵測由發布前之私有檢查負責。
12. **in-process 求解迴圈只讓出微任務,計時器不會觸發**(2026-11-08 實測):`workers: 0` 且無停止條件時,`setTimeout` 防懸置上限與 mocha 逾時皆不觸發(9 分鐘無輸出),測試被「卡死」而非判紅。凡可能因缺陷而無限迴圈之 in-process 案,一律另給 `maxRounds` 兜底(非被測條件);`workers > 0` 時主執行緒空閒,防懸置上限有效。
13. **閘(`opt.gate`)之停止傳遞**:停止傳遞有三層重疊——`stop()` 直送 `stop`＋旗標、閘後 `maybeStop` → `requestStop` 對全體 worker 送 `stop`、worker 端 `stopped` 旗標使 `go0`／`waitGo` 立即返回。故 `workers > 0` 時「閘內 `stop()`」單拿掉閘後檢查不會紅(設計重疊);能單獨驗到閘後檢查者為 in-process 之閘內 `stop()`、與 `workers > 0` 之閘內 `shouldStop`(旗標只由 `checkStop` 判定)。
14. **『不懸置』的測法**:讓一個 worker 之閘永不放行(測試持有 promise),以 `start()` 結算證明它被 `stop` 結束(`start()` 於全部 worker `exit` 後才結算);並以「該 worker 無任何 `round` 事件」證明它從未越過閘(若越過,start() 結算前其輪次必已回報,無須時間窗)。同步點用事件紀錄器之 `waitCount`(等第 N 個 `gate` 事件),閘內 `sleep` 只製造「閘等待中」之狀態。
15. **起跑前檢查的實際效益**:`workers > 0` 起跑前即使不查,`ready` 後的閘後檢查也使輪次為 0;起跑前檢查省下的是 worker 啟動與 `prepareSolve`(載入數據),故測試以「無 `ready` 事件、無閘呼叫」釘住,不以 `nRounds` 判定。
16. **接手殘留鎖不可「先移走、核對、不符再放回」**(2026-11-18 實測):以 `renameSync` 取走鎖檔後核對內容、不符再 `linkSync` 放回,於取走與放回之間鎖檔缺席,第三個行程之原子建立即成功 ⇒ 兩個持有者(6 個子行程同時接手同一殘留鎖,60 次中 1 次;另 3 次取得者之 `staleLock` 為 false)。改為:先以保護檔(`recompute.lock.takeover`,原子建立)使同時接手者只有一個進入,持有者核對鎖檔仍為所判定之殘留鎖,再以暫存檔改名覆蓋(鎖檔全程存在);改後 60/60 恰一個持有、`staleLock` 恆 true。**互斥類測試偶發失敗先量分布**:以獨立探測腳本(`test/tools/lockRaceProbe.mjs`)於同條件重複 N 次,統計「持有者數 ≠ 1」與各結果之比率,再判是測試或產品之缺陷;不放寬斷言、不重試。
17. **數字字串之轉型要在入口、且驗證不偏離回測套件之解析**:`toNumericUnit` 以 `cloneDeep` 取一次各欄後以 `buildBaseUnitNotional` 檢測、`cdbl`／`cint` 轉值;測試以 37 種寫法(空白、科學記號、`+`、`.5`、`'3.0'`、`'1e1'` 等)逐一比對轉換前後 `buildBaseUnitNotional(...).key` 與各價位之 `getNotional`,並以 getter 於第 2 次讀取回無效值證各欄只讀一次。`parseInt('1e1')` 為 1 而 `cint('1e1')` 為 10,故以 `parseInt` 取代之變異可被抓。
18. **回測套件對 `settings.uIni` 之數字字串:1.1.42 以下不轉型,1.1.43 起收並轉型(第 23 條已取代此條之重算結論)**:1.1.42 以下 `runStrategy` 以原字串運算,摘要靜默失真(已列〈回饋〉),故當時重算遇檔內 `settings.uIni` 為字串者,忠實重放即 `mismatch`(fail-closed)、`already` 之比較只轉 `unit`;**此結論於 1.1.43 起不成立**。本庫 cfg 層之 `uIni` 轉型仍在 `normalizeCfg`(給 `unit` 時)與重算之目標口徑入口完成(`normalizeCfg` 未給 `unit` 時 `settings` 原樣,屬本庫 cfg 層語意,不受回測套件版本影響)。
19. **「修前紅」之對照副本**:以 `git archive HEAD` 解到 `./tmp/<工作夾>/base`(原碼)、再 `patch -p1` 得提案原碼副本;副本位於套件根之下,相依經上層 `node_modules` 解析(免目錄連結);新測試放入副本跑,原碼之 `unit-baseUnit` 須以命名空間匯入(缺命名匯出時 ESM 連結失敗而整檔不載入)。變異副本須含 `package.json`(`recomputeStrategies` 之 `pkgVersionOf` 讀套件根,缺則 header 之版本為 `null` 而測試假紅)。
20. **未給 `unit` 時之前後對拍**(`test/tools/abPipeline.mjs`):載入階段凍結 `Date`(wsemi 之 `random` 以載入時刻為種子)後還原、`Math.random` 以固定種子替換、去重之普測用 1 個 worker;先證明同一版本連跑兩次逐位相同,再與基準副本比較(回傳、事件、`status` 與全部策略檔之遮蔽時間欄後雜湊)。
21. **本庫 `src/` 為 CRLF**(工作樹):`Edit` 工具保留行尾;以程式比對或替換原始碼片段時先把 `\r\n` 正規化為 `\n` 再比對。
22. **週期改為根數為本(w-data-trade 1.0.50;2026-11-18)**:各 calc 內建表之值為根數、標籤以每根 4hr 寫定,給 `opt.intervalSec` 後根數不變、標籤 = 根數 × 每根秒數;`opt.barsPerDay` 移除(再傳入為未知鍵,不報錯、不換算,故**舊碼配新版 w-data-trade 時非 4hr 不報錯而靜默得到 4hr 標籤**,只有測試抓得到)。實作要點:①檢核只經 `w-data-trade/src/resolvePeriods.mjs` 之 `chkIntervalSec`,其訊息為 `invalid opt.intervalSec: …`,`cfg` 端須捕捉後以固定訊息 `invalid cfg.intervalSec: …` 重拋(不含輸入值,上限取 `INTERVAL_SEC_MAX`);②`INTERVALS` 各值與期別標籤測試之期望值一律手寫(由「標籤 = 根數 × 每根時長」與「整日數寫 Nday、否則整小時寫 Nhr」推得,第 1 筆輸出於索引「根數 − 1」),不以現行碼產生;③非 4hr 標籤之測試要斷言**鍵集合恰為手寫表**(不只 `includes`),才抓得到舊語意殘留之鍵(如 1hr 之 `2day`);④變異腳本以字串站點替換時須確認站點**唯一**(JSDoc 內常有同字串,首次跑 `M2c` 即因站點出現 2 次而未變異);⑤4hr 等價對拍須同時含 1.0.19＋w-data-trade 1.0.49、1.0.19＋1.0.50 與新版三者,並以 1hr 數據證明比對有靈敏度。
