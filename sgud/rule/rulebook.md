> **藍圖**:以規則為單位記程式碼須長成什麼樣(附盤點指令與判準);與現況比對看 `../state/state.md`。規則 ID(TS-*)為穩定編號,不重編。路徑為套件根相對路徑;盤點指令於套件根執行(測試以 `npm test`)。

## 1. 套件邊界與發布面

- **TS-01 邊界**:`src/` 只 import 套件內相對路徑、node 內建模組(無 `node:` 前綴)、`package.json` 之 dependencies 所列套件(以 `src/` 深層路徑:`w-data-trade/src/WDataTrade.mjs`、`w-data-trade/src/resolvePeriods.mjs`〔`chkIntervalSec`、`INTERVAL_SEC_MAX`、`INTERVAL_SEC_BASE`;TS-11〕、`w-data-tdprovide/src/WDataTdprovide.mjs`、`w-data-csv/src/WDataCsv.mjs`、`w-dwdata-binance/src/saveData.mjs`、`w-dwdata-binance/src/intervals.mjs`、`w-trade-backtest/src/*.mjs`、`w-trade-solve/src/*.mjs`)與 wsemi 帶入之 `lodash-es/<函數>.js`、`wsemi/src/<函數>.mjs`、`dayjs`;不得引用任何使用端專案之程式與資料。
  - 盤點:`git grep -nE "from '(w-[a-z-]+|wsemi|lodash-es)'" -- src` 應為空(皆須深層路徑);`git grep -nE "from 'node:" -- src` 應為空。
  - 測試:`test/unit-package.test.mjs` ②。
- **TS-02 發布面**:`main` 指 `dist/w-trade-strategy.umd.js`(發布流程產製),**不設 `exports`、`files`、`type`**(下游以 `w-trade-strategy/src/…`、`w-trade-strategy/test/tools/…` 深層路徑取用);不提供 `.npmignore`(npm 包＝git 版控內容);`.gitignore` 列 `node_modules`、`tmp`、`test/_tmp`、`CLAUDE*.md`,不排除 `sgud`、`src`、`dist`、`test/tools`;scripts 只有 `test` 與 `deploy`;套件根有 `.editorconfig`、`.eslintignore`、`.eslintrc.js`、`.jsdoc`、`babel.config.js`、`SECURITY.md`、`LICENSE`(MIT)、`g.mjs`、`script.txt`、`toolg/` 六支。
  - 測試:`unit-package` ①③。
- **TS-03 無使用端痕跡(公開庫)**:`src/`、`test/`、`README.md`、`g.mjs`、`sgud/`、`toolg/`、`package.json` 不含使用端之專案名、目錄名、腳本名、本機路徑與規模數據;需求出處一律寫「使用端」與 Gitea 編號,來源管線稱「使用端既有管線」,實測稱「某實測」;公開之交易對代號(如 ETHUSDT)與公開 API 端點可保留;量化交易之業務詞為本套件之領域本身,不在此限。
  - 守門分工:`unit-package` ⑥ 只守**通用機敏樣式**(磁碟機絕對路徑、IPv4 位址、權杖／私鑰樣式),**不列任何使用端名稱**(列了即把名稱公開);使用端名稱之偵測由發布前之私有檢查負責,不在本庫。
  - 盤點(於套件根;命中僅應為 `test/unit-package.test.mjs` 之自檢字串〔中性假值〕):`git grep --untracked -nP "(?<![A-Za-z0-9_])[A-Za-z]:[\\\\/]" -- src test README.md g.mjs sgud toolg package.json` 與 `git grep --untracked -nP "(?<![0-9.])(\d{1,3}\.){3}\d{1,3}(?![0-9.])" -- <同上>`。
  - 測試:`unit-package` ⑥。
- **TS-04 JSDoc**:`src/` 每個匯出之函數須有說明、`@param`(有參數者)、`@returns`、`@example`;匯出之常數須有說明;可離線執行之 `@example` 其 `// =>` 須與實跑相符,需檔案系統或網路者首行寫 `need test in nodejs.`。
  - 測試:`unit-package` ⑤。
- **TS-05 範例 `g.mjs` 離線可跑**:以合成 K 線走完整條管線(外部數據來源、不連網、結束刪工作目錄),輸出與檔末 `// =>` 逐行相符;`README.md` 之 Example 含其全文。
  - 測試:`unit-package` ④。

- **TS-06 dist 打包寫法**:`toolg/gDistRollup.mjs` 以 `'./src'`、`'./dist'`、`fns: 'WTradeStrategy.mjs'`、`runin: 'nodejs'`;`external` 與 `globals` 同組且只含字串(node 內建模組:`src/` 與打包範圍內第三方套件所引用者;`dayjs` 與其 `plugin/utc.js`、`plugin/timezone.js`);**自有套件、`wsemi`、`lodash-es` 一律不列 external,由 rollup 沿引用打包進 dist**。
  - 為何:UMD 的 `require` 路徑對 ESM 外部模組取得命名空間物件(`{ default }`)而非預設匯出;自有套件(皆 ESM)列為 external 時,實測 `require` 載入 dist 後 `buildParams` 拋 `dataConvert is not a function`,且 `dist.readStrategies` 之 `typeof` 與 ESM 入口不同。ESM 專用之第三方套件(`strip-bom-stream` 等)同理須打包。
  - 盤點:自 `src/WTradeStrategy.mjs` 靜態追蹤 import 圖(含 `node_modules` 內之自有套件與第三方套件),取全部裸 import 歸類;新增依賴或自有套件升版後重盤。
  - 驗證:`node toolg/gDistRollup.mjs` 後,以 `require` 載入 dist,匯出鍵與 `typeof` 須與 `src/WTradeStrategy.mjs` 預設匯出一致,且實跑 `buildOhlc` → `buildParams` → `buildCache` 之產物與 ESM 逐位元組相同。
  - 限制:四個 worker entry(含 `src/recompute/recomputeStrategies_worker.mjs`,TS-19)不在 import 圖內,不隨 dist 打包(`toolg/gDistRollup.mjs` 檔頭第 6 點與 README 皆已註明)。
  - 測試:`unit-package` ②(external 寫法靜態守門;dist 本身為發布產製物,不入測試前提)。

## 2. 設定與契約

- **TS-10 設定鍵嚴格**:`normalizeCfg` 只認 `CFG_KEYS`(`src/cfg.mjs`),不認得之鍵拋錯並列可用鍵;已正規化之 cfg 可重入(衍生鍵 `DERIVED_KEYS` 略過);`createSolver` 之 opt 只認 `SOLVE_OPT_KEYS`(`src/solve/solve.mjs`;含 `EVENT_KEYS`,其中 `gate` 見 TS-16;另含 `w-trade-solve` 之 `thsCond`、`levelNumTradeBounds`,見 TS-21)。`CFG_KEYS` 含 `timeBasis`(TS-20)。新增讀取 `cfg.<鍵>`／`opt.<鍵>` 處須同步列入。
  - 測試:`unit-cfg`、`unit-solve`。
- **TS-11 時間與週期**:時間字串一律 `'YYYY-MM-DDTHH:mm:ss'`(wsemi `istime`),時區由 `cfg.timeZone` 決定(預設 Asia/Taipei);`interval` 為內建週期(`INTERVALS`)或另給 `intervalSec`(每根 K 線之秒數)。
  - **`intervalSec` 之檢核(跨套件規格 K4、K7、V19、V20;使用者 2026-11-18 定「給了無效值直接報錯,不退回預設」)**:依 `w-data-trade` ≥ 1.0.50 之 `chkIntervalSec`(深層路徑 `w-data-trade/src/resolvePeriods.mjs`,**不自寫一份**)檢核:60 之正整數倍且至多 31536000 之整數,數值或數字字串(轉為數值,檢測之值即使用之值);給了(非 `null`／`undefined`)而無效即拋 `invalid cfg.intervalSec: must be a positive integer multiple of 60 up to 31536000`(固定訊息、不含輸入值;`intervalSec(interval, fallback)` 之 `fallback` 亦同);**內建週期時另給之值亦檢核**(無效者拋,不退回預設;有效而不等於內建秒數者拋 `invalid cfg.intervalSec: must equal the seconds of the built-in cfg.interval`)。`INTERVALS` 之鍵與 `w-dwdata-binance` 之週期鍵一致(`1m`、`3m`、`5m`、`15m`、`30m`、`1hr`、`2hr`、`4hr`、`6hr`、`8hr`、`12hr`、`1day`、`1week`),各值須皆通過 `chkIntervalSec`(測試固定;以手寫表比對 `INTERVALS` 本身)。`INTERVAL_SEC_DEFAULT`(14400)為各相依套件「未給每根時長」之預設,亦為工作根口徑之預設(TS-22)。
  - **依因子名稱之期別段**:`src/` 不依期別段做任何判斷(`isKeyCloseOnly` 只讀第 3、5 段,`classifyKeys` 只讀前綴與 `_vbs_`);期別標籤反推根數一律用 `w-data-trade` 之 `periodInfo`(測試之標籤對應亦以之與 `spanLabelOf` 推導;方向改變法之門檻標籤 `${門檻}pct` 不是時間跨度,`w-data-trade` ≥ 1.0.58 之 `periodInfo` 對之回 `{ bars: 0, spanSec: 0 }`〔同 `none`〕,見 TS-27)。盤點:`grep -rnE "[0-9]+(hr|day)" src` 之命中只應在註解與 JSDoc 範例。
  - **`buildParams` 內之每根秒數一律為 `cfg.intervalSec`**:交給 `dataConvert` 之各 method 之 `optMethod.intervalSec` 皆設為 `cfg.intervalSec`(含不讀選項之 `orig`;`w-data-trade` 要求同一次呼叫之各 method 同值,否則拒絕且輸出夾為空);交給 `dataCalibrate` 之 `optMethodInit`／`optMethodRef` 去除 `intervalSec`,並明列 `opt.params` 為 `optMethodInit` 之各鍵(只校正偏移參數);凍結於 `meta.optMethod` 者不含 `intervalSec`。盤點:`grep -n "withIv\|omitIv\|params: Object.keys" src/params/buildParams.mjs`(站點:Pass A 兩處 `omitIv`〔不校正之凍結、校正之起點與參考〕、Pass B 兩處 `withIv`〔nm 探測與寫出〕)。
  - **時刻格線**:非 4hr 時 `buildOhlc` 於寫檔前以 `checkBarGrid` 核對(由下載套件保證對齊,本套件仍核對回來之序列):相鄰時差為每根秒數之正整數倍、`timeBegin` 與訓練期各界線落在價格序列之格線上、溢價指數與價格同一格線;不合即拋 `invalid <price|index> series: must have bar times spaced by positive multiples of cfg.intervalSec`／`invalid index series: must have bar times on the bar grid of the price series (cfg.intervalSec)`／`invalid cfg.<timeBegin|train.timeStart|train.timeEnd|train.timeEndByMode.long|train.timeEndByMode.short>: must be on the bar grid of the <price|index> series (cfg.intervalSec)`(訊息依 V19、V20,不含輸入值)。**4hr 不核對格線、不判定期間內之洞**(維持既有行為;**使用者 2026-11-19 裁定之刻意範圍**:幣安資料本身即有缺根處,故 **4hr 之缺根不會被攔下**;4hr 而由下載套件合併者〔如東京之 4hr〕亦同,其未輸出之目標根見 `meta/aggregate.json`;非遺漏,不得因「一致性」而補上)。
